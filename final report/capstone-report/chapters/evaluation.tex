\chapter{Investigation and Evaluation}

\section{Experimental Investigation}

\subsection{Evaluation questions and protocols}

The investigation tests three hypotheses: (H1) temporal models can learn useful
physical-PAD evidence; (H2) strong source-domain performance will decline under a
shift from physical spoofs to high-quality digital manipulation; and (H3)
manipulation-specific specialists with a learned router can outperform one
universal frame detector on a controlled in-domain split.

The physical/deepfake transfer study uses LCC-FASD, Celeb-DF-v2, and Asian-Fakes.
Two saved protocols are compared for each of $G^2V^2$former and GD-FAS: training
on LCC-FASD, and then fine-tuning the resulting model on Celeb-DF-v2. All three
datasets are evaluated after each stage. This is a demanding domain shift because
physical replay/print cues and digital synthesis cues are not interchangeable.
Celeb-DF-v2 itself was constructed to reduce the obvious artefacts of older
deepfake data \cite{li2020celebdf}.

The Xception study uses FaceForensics++ C23. Validation is group-disjoint from
training at the source-video group level. The universal detector sees original
and all five fake methods. Each specialist sees original versus one method. Two
legacy routers---a CNN head and XGBoost---predict one of six original/method
classes from embeddings and then dispatch to a specialist or apply the original
fallback. This protocol answers an in-domain routing question only; it is not an
unseen-generator or production-liveness evaluation.

\subsection{Metrics}

Let bona fide be the negative class and attack/fake the positive class. Accuracy
can be inflated by class imbalance, so balanced accuracy and class-conditional
rates are reported. For PAD experiments,

\begin{align}
\mathrm{APCER} &= \frac{\text{attacks classified as bona fide}}{\text{all attacks}},\\
\mathrm{BPCER} &= \frac{\text{bona fide classified as attack}}{\text{all bona fide}},\\
\mathrm{HTER} &= \frac{\mathrm{APCER}+\mathrm{BPCER}}{2}.
\end{align}

ROC-AUC measures ranking across thresholds; average precision (AP) is informative
under fake-heavy class balance. None of these, by itself, establishes calibrated
probability, robustness to injection, or a financially acceptable operating
point. ISO/IEC 30107-3 reporting should be followed for a formal PAD evaluation
\cite{iso30107}.

These results do not show that temporal information is unhelpful. They show that
temporal modelling does not remove the need for representative domains and
generator diversity. A model may learn the motion of print/replay attacks while
missing temporally plausible face swaps. Conversely, GD-FAS's source result does
not prove digital manipulation generalisation. The appropriate conclusion is
that attack taxonomy, training domains, and evaluation domains must be reported
together.

An earlier ROSE-Youtu MobileNetV3 temporal experiment recorded 98.46\% accuracy,
99.88\% AUC, 1.39\% EER, and 1.36\% HTER. It is retained as evidence that the
lightweight temporal approach can perform strongly on the earlier physical-PAD
protocol, but it predates the exported mobile checkpoint and must not be quoted
as that checkpoint's performance.

Before the numerical-stability fix described in Section~\ref{ch:design}, the
project's earlier G$^2$V$^2$former-based prototype was evaluated on the 342-video
LCC-FASD development split (300 spoof, 42 live), giving 72.8\% accuracy, 80.5\%
ROC-AUC, and 26.6\% HTER at an equal-error threshold of 0.239.
\Cref{fig:prelim-confusion,fig:prelim-roc} show the resulting confusion matrix
and score distribution: 81 of 300 spoof samples were accepted as live, which the
earlier report itself judged unacceptable for a security-critical deployment.
This result is retained as the honest starting point of the project rather than
omitted; the subsequent scatter-mean/clamping fix and 20-epoch fine-tuning run
discussed below improved on it, and the separate MobileNetV3 screening stage
discussed next improved on it further.

Two conclusions follow. First, GPU-served routing is materially faster than
evaluating every specialist: 14.6~ms against 50.9~ms, a 3.5$\times$ reduction,
because only the router and the one selected expert run per frame instead of
all five. Second, the server path is only worth its network round trip when GPU
serving is available---the CPU figure (367~ms) is close to two orders of
magnitude slower than the routed GPU path, which is why the server stage should
not be assumed interchangeable across hosting tiers without re-measuring. These
figures were obtained on the deployed FastAPI/ngrok endpoint described in
Section~\ref{ch:design} rather than in a research notebook, so they are closer
to serving conditions than the $G^2V^2$former pilot below, though still a
single-host measurement rather than a load-tested service-level guarantee.

The inspected $G^2V^2$former latency pilot used five runs on an NVIDIA T4 and
reported a mean of 1,315.45 ms per video end-to-end, of which 134.56 ms was model
inference. The small run count and cloud GPU environment make this a diagnostic,
not a production latency guarantee. The difference between total and model time
also shows that face/landmark preprocessing and data handling deserve
optimisation, and it explains why the deployed second stage in
\Cref{tab:latency} uses the Xception router path rather than $G^2V^2$former.

The 21.71\% figure quoted in the earlier project paper and the 22.38\% figure in
\Cref{tab:transfer-results} are reconciled as two different runs rather than a
discrepancy to resolve by rerunning. The earlier paper reports an LCC-FASD-only
extended fine-tuning run of 20 epochs after the numerical-stability fix
described in Section~\ref{ch:design}: HTER fell from a 26.6\% preliminary-prototype
baseline to a best-epoch value of 21.71\%, but continued to fluctuate rather than
converge (final-epoch HTER 30.98\%), which that paper attributes to LCC-FASD's
small training partition (992 videos). \Cref{fig:g2v2-epochs} plots this run.
\Cref{tab:transfer-results} instead reports one checkpoint selected under the
later common protocol used to compare $G^2V^2$former with GD-FAS, so that both
models are read at a consistently defined stage rather than each at its own
single best epoch; 22.38\% is therefore the fairer number for the
cross-model comparison in this report, and 21.71\% remains the lower bound the
architecture reached before common-protocol checkpoint selection was adopted.

\begin{figure}[H]
  \centering
  \includegraphics[width=\textwidth]{g2v2former_epoch20.png}
  \caption{HTER and AUC per fine-tuning epoch on the in-domain LCC-FASD split
  and the held-out Celeb-DF-v2 deepfake benchmark, with the resulting
  generalisation gap below. The gap averages approximately 30 points of HTER and

  \label{fig:g2v2-epochs}

That earlier zero-shot run offers a more detailed account of the transfer
failure than a single-epoch number can: across all 20 epochs, Celeb-DF-v2 HTER
stayed in the 55--62\% range and its AUC was almost entirely below the 50\%
chance level, with one exception epoch reaching 48.53\% HTER that coincided with
the run's best in-domain checkpoint rather than showing a stable trend. The
paper's own explanation is that presentation attacks are physical re-capture
artefacts---moir\'e interference, specular reflection, reduced dynamic
range, geometric planarity---which are exactly the local photometric and
pseudo-3D cues $G^2V^2$former's visual and landmark streams are built to detect,
whereas deepfakes are digital generation-side artefacts (blending-boundary
inconsistency, generator frequency fingerprints, independent-frame temporal
flicker) that the architecture, as trained here, has no explicit mechanism to
detect. That explanation is retained in this report as the working hypothesis
for the domain gap, not as a claim independently verified beyond the cited run.

\begin{figure}[H]
  \centering
  \includegraphics[width=\textwidth]{g2v2former-attention.png}
  \caption{Spatial and temporal attention on a live face video (a) versus a 3D
  mask presentation attack (b): attention concentrates on mask edges and
  texture, the exact physical re-capture cues discussed above. This is direct
  evidence of what the model has learned to look for, and why that evidence is
  the wrong kind for a digital deepfake, which has no mask edge to attend to.
  Derived from \cite{yang2024g2v2} using the attention-relevance method of
  Chefer et al. (c).}
  \label{fig:g2v2-attention}
\end{figure}

GD-FAS's own mechanism is informative for the same reason. \Cref{fig:gdfas-internals}
shows how its group-wise scaling and Gram-Schmidt orthogonal decomposition align
classifier weights and biases \emph{across the presentation-attack source
domains it is trained on}: it explicitly targets known domain shift (camera,
lighting, subject population) within one attack family, not shift to a
different attack family. That is consistent with \Cref{tab:transfer-results}:
GD-FAS's in-domain LCC-FASD result is the strongest of any model in this report,
but its zero-shot Celeb-DF-v2 result is close to chance, because the mechanism
in \Cref{fig:gdfas-internals} has nothing to align against a domain it never
saw during training. Both architectures, in short, are only as broad as the
attack family they were trained on; neither generalises to an attack family
its training data and loss function were not built to represent.

\begin{figure}[H]
  \centering
  \includegraphics[width=\textwidth]{gdfas-internals.png}
  \caption{How GD-FAS aligns decision boundaries across its presentation-attack
  source domains: Group-wise Scaling Loss balances per-domain learning scale
  (left), the Gram-Schmidt process projects live/spoof and domain
  invariant/specific directions (centre), and Feature Orthogonal Decomposition
  pulls invariant features together while pushing domain-specific features
  apart (right). Nothing here references a domain outside the training set.
  Reproduced from \cite{jung2025gdfas}.}
  \label{fig:gdfas-internals}
\end{figure}

The result supports a narrow conclusion: under the saved group-disjoint,
in-domain FF++ protocol, method-conditioned specialist selection improves a
universal Xception baseline. It does not demonstrate robustness to unseen
generators, external datasets, recapture, injection, video-level aggregation, or
deployment demographics. It also incurs an expert-training and storage cost that
must be compared with stronger universal or multi-task baselines.

\section{Deviations and Design Revisions}

The main deviations are substantive and should remain visible in the final report:

\begin{enumerate}
  \item The planned three-tier system was narrowed to an integrated mobile first
        stage and separately tested server candidates; no reviewer interface was
        completed.
  \item The temporal MobileNet training code uses 10-frame clips in one path,
        whereas export/inference/application code uses 24; the final artefact
        cannot inherit earlier metrics without provenance evidence.
  \item $G^2V^2$former checkpoint metrics differ between the latest PDF and saved
        artefacts and require one reproducible final evaluation.
  \item Strong physical-PAD performance did not transfer to digital deepfakes,
        motivating GD-FAS comparison and manipulation-specific Xception work.
  \item The routing notebook added an original class, although the intended
        meta-router only selects among five specialists. Its useful six-way result
        is reported honestly, and the corrected five-way experiment is future work.
  \item Capture-channel attacks became an explicit system concern. Media analysis
        alone is no longer represented as sufficient protection from injection.
\end{enumerate}

These revisions improve the report's validity: they separate demonstrated
evidence from architecture intent and convert unresolved contradictions into
testable follow-up work.
